# 青禾报销助手\_zxr

> 智能报销问答助手 —— 制度自助查询 + 单据状态授权查询

## 一、项目背景

本项目源于陈工（FDE 工程师）在青禾科技的现场观察：



* **乔姐**（行政专员）每天反复回答 "报销需要什么材料"" 住宿标准是多少 " 等制度问题

* **周敏**（财务专员）每天反复帮员工查 "我的报销到哪一步了"

* **小林**（普通员工）出差回来，想一次备齐材料、再查自己的单据进度

**项目目标**：先让员工自助查有效制度，再扩展为经授权查询本人单据状态；制度仍由乔姐维护，业务事实仍由周敏核对。

* **本仓库**：提供一个**零依赖、可立即运行的 Python 原型**，完整演示架构和核心流程，用于验证需求和演示，后续可平滑迁移到 MaxKB。

## 四、快速开始

### 环境要求



* Python 3.10+（已在 3.14 验证）

* 依赖仅 `pyyaml`

### 安装与初始化



```
# 1. 安装依赖
pip install pyyaml

# 2. 初始化数据库（创建三位主角账号 + 示例单据）
python scripts/init_db.py

# 3. 启动对话
python main.py
```

## 六、核心功能实现说明

### 6.1 员工自助查有效制度（第一阶段）



* `policy_kb.py` 扫描 `data/policies/*.md`，解析头部元数据（编号、版本、状态、维护人）

* 按 `##` 章节切分，中文滑窗关键词匹配检索

* **只返回 "状态 = 有效" 的制度**；已撤回制度不会出现在员工视图

* 回复附带制度编号和版本，便于追溯

### 6.2 经授权查询本人单据状态（第二阶段）



* 员工首次查询单据时，必须先输入 "授权查询我的单据"

* 授权后，`document_db.get_documents_by_employee()` 只返回 `employee_id` 匹配的记录

* 财务（周敏）不受此限制，可查看全部单据并更新状态

### 6.3 制度仍由乔姐维护



* 乔姐将新制度 `.md` 文件放入 `data/policies/` 即可

* 制度头部按现有格式写明元数据（编号、版本、状态、发布日期）

* 对乔姐说 "刷新制度" 即可热加载，无需重启服务

* 撤回制度：将 `.md` 中 "状态" 改为 "已撤回"，再刷新

### 6.4 业务事实仍由周敏核对



* 单据状态流转（部门审批→材料审核→财务复核→打款）由周敏在系统中操作

* 智能体**不自动判断**单据进度，只展示周敏核对后的状态

* 回复末尾固定提示："以上业务事实由周敏核对确认"

## 七、生产迁移路线

本原型验证需求后，建议按以下路线迁移到生产：



1. **知识库迁移**：将 `data/policies/` 下的 Markdown 导入 MaxKB 知识库，获得向量检索、引用追溯、版本管理能力

2. **单据接口对接**：用 MaxKB 的 MCP 工具或工作流 HTTP 节点，对接 OA / 财务系统的真实单据查询 API

3. **身份集成**：接入企业 SSO（飞书 / 钉钉 / 企微），自动识别用户身份和权限，替代本原型的 `login` 模拟

4. **前端嵌入**：用 MaxKB 的 iframe 嵌入或 SDK，将助手嵌入企业 IM

5. **人工兜底**：复杂问题自动转人工（乔姐 / 周敏），保留现有业务流程不变
