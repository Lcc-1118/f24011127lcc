# 02 · 一页纸需求清单（v1.0，定稿）

> 一页纸的用途：任何争议回到这一页裁决。超出本页的都属于"非本期目标"。

## 1. 一句话定位

面向企业员工的**报销制度助手 + 报销单草稿智能体**：员工用自然语言问制度、验发票、发起报销；管理员维护制度知识库、提示词模板并审计对话。系统**只产出草稿**，不向财务系统提交。

## 2. 用户与角色

| 角色 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| 员工（`role=employee`） | 问制度、校验发票、生成并确认自己的报销单草稿、看自己的草稿 | 进管理后台、看他人会话、改制度与提示词 |
| 管理员（`role=admin`） | 上传/删除制度、重建切片、编辑系统提示词、按人/时间审计对话、看工具调用日志 | 修改员工已确认的草稿金额（只能标记与备注） |

## 3. 必须由代码判定的六条硬规则（不由大模型判断）

| # | 规则 | 判定位置 |
| --- | --- | --- |
| R1 | 报销时效：费用发生日起 **90 个自然日**内提交，超期不予受理 | `rules.deadline_check` |
| R2 | 住宿上限：城市等级 × 职级（一线 800/600/500；新一线 650/500/400；其他 500/400/300 元/晚，含税） | `rules.lodging_cap` |
| R3 | 伙食补助：一线 100 / 新一线 80 / 其他 60 元/天，当天往返按半天 | `rules.meal_allowance` |
| R4 | 发票合规：抬头必须是公司全称，纳税人识别号必须准确，否则一律不予报销 | `rules.validate_invoice_fields` |
| R5 | 发票查重：按发票号全局唯一，重复报销直接拒绝并指出被哪张草稿占用 | `tools._tool_validate_invoice` |
| R6 | 审批链路：≥5000 加部门负责人；≥20000 再加财务总监 | `rules.approval_chain` |

补充硬规则：实习生按普通员工 **80%** 执行；禁报名目（礼品/烟酒/娱乐/罚款/滞纳金）直接判不合规；建单前必须 `validate_invoice` 通过（代码闸门，非提示词约束）。

## 4. 功能范围（本期必须交付）

**员工端**
- 制度问答：混合检索（BM25 + 向量，RRF 融合）Top3，回答必须带条文引用，无依据时明确说"制度中未找到"。
- 发票校验：输入发票号/金额/日期/科目 → 给出通过或不通过 + 逐条问题 + 依据条款。
- 发起报销：查制度 → 查额度 → 索要素材 → 校验 → 生成草稿 → **中断等待员工确认** → 落库并给出审批链路。
- 会话管理：多会话、历史还原、最近 6 轮上下文。

**管理端**
- 制度知识库：上传 md/txt/pdf → 自动切片（500 字，50 字重叠）→ 入库 → 立即可检索；同名上传自动归档旧版；可删除、可重建切片、可查看切片明细。
- 提示词模板：`system_qa` / `system_agent` 可在页面编辑，保存即 `version+1`，下一轮对话立即生效（存库，不写死代码）。
- 对话审计：按员工、时间区间、是否已标记筛选；命中"不要发票/多开/虚开/拆单/凑票/绕过审批"等关键词仅作**人工复核提示**，不自动定性。
- 运行日志：工具调用轮次、工具名、参数、耗时、结果摘要。

## 5. 非功能要求

| 维度 | 要求 |
| --- | --- |
| 性能 | 制度检索单次 < 200ms（本地 SQLite + 内存索引）；SSE 首字 < 1s（离线模式） |
| 并发 | 单机 Uvicorn，目标 20 并发在线；LLM 调用按供应商配额限流（清单见 10 号文档） |
| 可用性 | 模型不可用时降级为"只给条文 + 人工判断"，功能不整体不可用 |
| 数据 | SQLite WAL；`db_path` 可配；备份=文件级拷贝 |
| 安全 | JWT（httpOnly Cookie，12h）；越权访问按 404；密码 PBKDF2-SHA256（12 万次迭代）；页面上发票号掩码 |
| 可维护 | 业务规则与提示词分离；提示词改库即生效；模块零第三方依赖（除 Web 层的 FastAPI/Jinja2） |
| 可复现 | 无 API Key 也能完整演示与跑评测（离线规则大脑） |

## 6. 验收标准

1. `python run.py` 一条命令起服务，员工与管理员的全部主路径可点通（见 11 号文档的手工验收清单）。
2. `python scripts/smoke_e2e.py` 全绿（当前 30/30）：登录鉴权、SSE 事件链、确认闸门、知识库上传生效、提示词版本自增。
3. `python evals/run_eval.py` 通过率 ≥ 90%，且 3 条陷阱题 100% 回答"制度中未找到"（当前 30/30）。
4. 任何建单路径都无法绕过 `validate_invoice`（用"直接建单"的对话验证会被 `VALIDATION_REQUIRED` 拦住）。
5. `python quickstart.py` 单文件演示跑通，无需配置环境变量与 API Key。

## 7. 明确不做（本期）

- 不做真实 OA/ERP 提交、不做发票 OCR、不对接税务查验平台。
- 不做多租户、不做按时点检索历史制度版本。
- 不做移动端 App（响应式网页已够用）。
- 不引入向量数据库（FAISS/Milvus）：切片量级小，哈希向量 + BM25 已满足，减少部署面。
