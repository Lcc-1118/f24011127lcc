# 07 · 管理后台设计（页面清单 + 接口清单）

> 对应提示词 5。服务端渲染（Jinja2），风格类 SaaS，无前端框架、无 CDN。
> 页面：`app/web/templates/admin_*.html`；路由：`app/web/admin_routes.py`（`prefix="/admin"`）。

## 1. 权限模型

| 角色 | 值 | 能进的地方 |
| --- | --- | --- |
| 员工 | `employee` | `/chat`、`/my/drafts`、自己的会话 |
| 管理员 | `admin` | 以上 + `/admin/*` 全部 |

实现是三层，缺一层都能被绕过：

1. **页面守卫** `_admin_page()`：未登录 → 303 `/login?next=...`；已登录但非管理员 → 渲染 `forbidden.html`，**返回 403**（不是 200，否则监控看不出来）。
2. **接口守卫** `require_admin()`：所有 `POST /admin/*` 与 JSON 接口一律 403 `E_FORBIDDEN`。
3. **数据归属** `_own_session()`：员工读会话前校验 `session.user_id == user.id`，不匹配按 404 处理（避免泄露"这个 id 存在"）。

JWT 用 HS256 手写实现（`app/security.py`，`pbkdf2$120000$salt$hash` 存密码），不引入 `python-jose`——只有一个签名算法，80 行代码足够，少一个供应链依赖。

## 2. 页面清单（6 个）

| # | 路由 | 页面名 | 核心内容 |
| --- | --- | --- | --- |
| 1 | `GET /admin` | 运营总览 | 8 个指标卡（用户/会话/消息/报销单/制度文档/切片数/审计标记/工具调用）、工具调用分布（`per_tool` 聚合）、最近 12 条对话、当前模型模式（`heuristic` / `llm:deepseek-chat`）、`max_rounds=5` |
| 2 | `GET /admin/policies` | 制度知识库 | 文档表格（标题/版本/切片数/状态/上传人/时间）+ 上传表单 + 每行的"重切片""删除" |
| 3 | `GET /admin/policies/{id}` | 文档详情 | 该文档全部切片列表（序号/所属小节/字数/正文前 200 字），用于核对切片是否切断表格 |
| 4 | `GET /admin/prompts` | 提示词模板 | 两个模板（`system_qa` 问答口径 / `system_agent` 智能体口径）的文本框 + 版本号 + 更新时间 + "保存" |
| 5 | `GET /admin/audit` | 对话审计 | 筛选（员工 / 起止日期 / 只看已标记）+ 消息列表 + "标记可疑"按钮 + 已标记项"已处理"按钮 |
| 6 | `GET /admin/logs` | 智能体日志 | `agent_logs` 明细：轮次 / 工具名 / 参数 JSON / 结果摘要 / 耗时 ms |

## 3. 接口清单

### 3.1 制度知识库

| 方法 | 路径 | 入参 | 行为 |
| --- | --- | --- | --- |
| `POST` | `/admin/policies` | multipart：`file`、`title`、`version`、`effective_date` | 校验扩展名（`.md/.txt/.pdf`）与大小（≤ 8MB）→ PDF 用 `pypdf` 抽文本 → 抽不到 20 字报 `E_EMPTY_DOCUMENT` → 同名旧文档置 `archived`（保版本）→ 插入新文档 → `rebuild_chunks()` 切片入库 → 303 回列表 |
| `POST` | `/admin/policies/{id}/rechunk` | — | 删旧切片重建（改了 `chunk_size` 或怀疑切片切断表格时用） |
| `POST` | `/admin/policies/{id}/delete` | — | 逻辑删除（`status='deleted'`），同时让索引缓存失效 |
| `GET` | `/admin/policies/{id}` | — | 文档详情页 |

**为什么"同名不覆盖而置 archived"**：制度换版本时，历史对话引用的旧条文必须还能查到。物理覆盖会让审计失去依据。

**索引何时生效**：`get_index(conn)` 用 `(doc_id, updated_at)` 做签名缓存，上传后第一次问答自动重建，无需重启服务——这条在 `scripts/smoke_e2e.py` 里被显式验证过（上传一个临时制度 → 立刻提问 → 能检索到 → 删除 → 再问就检索不到）。

### 3.2 提示词模板

| 方法 | 路径 | 入参 | 行为 |
| --- | --- | --- | --- |
| `GET` | `/admin/prompts` | — | 列表页 |
| `POST` | `/admin/prompts/{key}` | form：`content` | `version = version + 1`，写 `updated_by`；**下一轮问答立即生效**（引擎每轮从 `get_prompt()` 读，不缓存） |

`key ∈ {system_qa, system_agent}`。默认 `system_qa` 内容就是提示词 5 给的那段：

> 你是公司报销制度助手，只根据提供的制度条文回答，不确定时明确说"制度中未找到"，回答末尾附引用来源，不得编造报销标准。

**为什么必须存数据库**：口径是运营资产，不是代码。改"要不要在回答里加免责声明"这种事，不该走一次发版。

`system_agent` 额外加了四段（完整内容见 `docs/08`）：
1. 可用工具与各自适用场景；
2. **顺序约束**：`create_draft` 前必须 `validate_invoice` 通过；
3. 只能在"用户明确要报销"时建单，不能用"我觉得他需要"来推断；
4. 引用与拒答口径。

### 3.3 对话审计

| 方法 | 路径 | 入参 | 行为 |
| --- | --- | --- | --- |
| `GET` | `/admin/audit` | query：`user_id`、`date_from`、`date_to`、`only_flagged` | 列表页 |
| `POST` | `/admin/audit/{message_id}/flag` | form：`reason`（可空） | 插入 `audit_flags(message_id, reason, flagged_by, status='open')` |
| `POST` | `/admin/audit/flag/{flag_id}/resolve` | — | `status='resolved'` |

**"疑似违规"怎么标**：两条路并行，都不自动定性。

1. **关键词提示**（`SUSPICIOUS` 列表：不要发票 / 多开 / 虚开 / 拆单 / 凑票 / 代开 / 绕过审批 / 开大 / 开高 / 换科目），命中就在列表里打一个"⚠ 待复核"黄标。
2. **人工标记**：管理员看完整对话后点"标记可疑"，写理由。

**明确不做自动拦截**：关键词命中率高但误报也高（"虚开发票是违法的对吧"这种正常提问会命中）。这里是审计线索，不是风控判决——真正的拦截在 `validate_invoice` 与 `create_draft` 的代码闸门里。

### 3.4 智能体日志

`GET /admin/logs` 直接读 `agent_logs`：

| 字段 | 含义 |
| --- | --- |
| `round_no` | 第几轮决策（0 表示建单这类"确认后补执行"的动作） |
| `tool_name` | 工具名 / `llm_decision` |
| `args_json` | 入参（**发票号已脱敏为前 4 位 + `****`**） |
| `result_summary` | 结果摘要（≤ 200 字） |
| `duration_ms` | 耗时 |

这张表是提示词 7 的"每轮决策记录"要求，也是后续调优（换模型、改提示词后工具选择是否变好）的唯一数据来源。
