## 3. "一个文件直接运行"说的是哪个

```bash
python quickstart.py
```

不需要装任何包、不需要 API Key，直接跑出三个场景：

1. **制度问答**：`出差上海3天住宿标准是多少` → 调 `search_policy` + `query_expense_standard` → 答"一线/普通员工/500 元一晚/伙食 100 一天/3 天 300"；
2. **票据陷阱**：`公司有健身房补贴吗` → 答"制度中未找到相关规定"（不硬凑条文）；
3. **建单确认**：`帮我报上个月去北京的差旅，发票号 87654321，金额 480 元` → 查制度 → 算标准 → 校验发票 → **中断**要求确认 → 确认后落库并给出审批链路。

想看完整 UI：`python quickstart.py --web`（或 `python run.py`）。

## 4. 怎么推上来的（没有本地 git 也能推）

本机没有 git，也没有 gh CLI，所以走 **GitHub REST API（Git Data API）** 直接建 blob/tree/commit：

1. `GET /repos/Lcc-1118/f24011127lcc` 拿默认分支与当前 commit；
2. 对每个文件 `POST /git/blobs`（`content` 用 base64，`encoding=base64`）；
3. `POST /git/trees`（带 `base_tree`）一次性提交全部路径；
4. `POST /git/commits` + `PATCH /git/refs/heads/main`。

好处：不依赖工作区清洁、不产生中间历史；坏处：拿不到 git 增量，大仓库要分批（本仓库 60 个文件，一次到位）。

> 踩过的坑：Fine-grained PAT 的 Repository access 若选 "Public repositories（Read-only）"，即使仓库页显示 `permissions.push=true` 也会 403（`Resource not accessible by personal access token`，响应头 `x-accepted-github-permissions = contents=write`）。必须选 "Only select repositories" 并把 **Contents** 设为 **Read and write**。

> 安全提醒：推送用的 Fine-grained PAT 只在本机临时使用，**没有写进仓库任何文件**（`.gitignore` 已忽略 `.env`）。

## 6. 还没做的（诚实清单）

1. **多 worker 部署**：SQLite 写锁在多进程下会打架，要上 2 个以上 worker 得换 Postgres（`db.py` 用一个薄层封装，改起来集中）。
2. **OCR**：发票拍照识别没做，靠员工手输号码。
3. **真实审批流对接**：当前只到"草稿 + 审批链路预览"，`submit_approval` 留给 OA 系统。
4. **配额与限流**：无单用户 LLM 调用配额，见 `docs/11` 第 2 节。
5. **真模型评测**：`evals` 跑的是确定性大脑；接真模型后要再跑一轮，看工具顺序是否依然稳定。
6. **语义向量**：当前是 512 维哈希（零依赖），换真 embedding 后 recall 还能涨，但会引入网络依赖。
