# 06 · 员工端聊天接口与前端设计

> 对应提示词 4。提示词要求"先给接口设计，确认后再给完整代码"，本文件就是那份接口设计；代码已按此实现（`app/web/chat_routes.py`、`app/web/static/chat.js`）。

## 1. 统一约定

**认证**：JWT 放 httpOnly Cookie `reimb_token`（`SameSite=Lax`，12 小时）。之所以不用 `Authorization` 头 + localStorage：SSE 用 `fetch` 发起时 Cookie 会自动携带，而 localStorage 方案要手写头；且 httpOnly 让 XSS 拿不到 token。

**错误格式**（所有 JSON 接口统一，中文文案直接可展示）：

```json
{ "ok": false, "code": "E_SESSION_NOT_FOUND", "message": "会话不存在或无权访问" }
```

| code | HTTP | 触发条件 |
| --- | --- | --- |
| `E_UNAUTHORIZED` | 401 | 未登录 / token 过期 |
| `E_FORBIDDEN` | 403 | 越权（员工访问管理接口） |
| `E_SESSION_NOT_FOUND` | 404 | 会话不存在**或属于别人**（不给攻击者探测空间） |
| `E_EMPTY_QUESTION` | 400 | 问题为空 |
| `E_QUESTION_TOO_LONG` | 400 | 问题超过 2000 字 |
| `E_NO_PENDING_DRAFT` | 400 | 确认时没有待确认草稿（重复确认也走这里） |
| `E_LLM_UNAVAILABLE` | 503 | 模型调用失败且无法降级 |

## 2. 接口清单

### 2.1 `POST /api/sessions`

新建会话。

```json
// 请求
{ "title": "上海出差报销" }        // 可空，默认"新会话"
// 响应 201
{ "ok": true, "session": { "id": 12, "title": "上海出差报销", "created_at": "2026-11-05 10:31:02" } }
```

### 2.2 `GET /api/sessions`

列出我的会话（按 `updated_at` 倒序，最多 50 条）。

```json
{ "ok": true, "sessions": [ { "id": 12, "title": "上海出差报销", "updated_at": "..." } ] }
```

### 2.3 `GET /api/sessions/{id}/messages`

回填历史（切换会话时用）。

```json
{
  "ok": true,
  "messages": [
    { "id": 88, "role": "user", "content": "出差上海3天住宿标准是多少", "created_at": "..." },
    { "id": 89, "role": "assistant", "content": "上海属一线城市…",
      "citations": [ { "doc_title": "费用报销管理制度（示例）", "heading": "2.2 住宿标准", "text": "…" } ] }
  ],
  "pending": null            // 或 { "draft": { "items": [...], "total": 480 } }
}
```

`pending` 非空表示"上次停在确认槽"，前端要直接把确认卡片重新摆出来——否则用户刷新页面就再也点不到那张草稿的确认按钮。

### 2.4 `POST /api/chat`（核心，SSE）

```json
// 请求
{ "session_id": 12, "question": "帮我报上个月去北京的差旅，发票号 87654321，金额 480 元，日期 2026-10-20" }
```

响应 `Content-Type: text/event-stream`，每帧 `data: {json}\n\n`，帧序如下：

| 事件 `type` | 载荷 | 前端行为 |
| --- | --- | --- |
| `status` | `{"text":"正在检索制度…"}` | 显示状态条 |
| `tool_call` | `{"name":"search_policy","args":{...},"round":1}` | 折叠区打印"调用 search_policy" |
| `tool_result` | `{"name":"...","ok":true,"summary":"命中 3 条","duration_ms":7}` | 折叠区打印结果摘要 |
| `token` | `{"text":"上海"}` | 打字机追加 |
| `citations` | `{"items":[{doc_title,heading,text}]}` | 回答底部渲染引用卡 |
| `confirm_required` | `{"draft":{"items":[...],"total":480,"approval_chain":[...]}}` | 弹出确认卡片，锁住输入框 |
| `done` | `{"rounds":3,"model":"heuristic"}` | 结束，解锁输入 |
| `error` | `{"code":"E_LLM_UNAVAILABLE","message":"..."}` | 红色错误条 |

`confirm_required` 之后服务端**不再产出 token**——这是强制的：草稿没确认就不能建单，模型也不能"一边说已建好一边等确认"。

### 2.5 `POST /api/chat/confirm`

```json
// 请求
{ "session_id": 12, "accepted": true }   // accepted=false 走拒绝分支
// 响应
{ "ok": true, "draft_id": 7, "total": 480.0,
  "approval_chain": ["直属主管审批", "财务审核", "出纳付款"] }
```

拒绝时返回 `{"ok":true,"accepted":false,"message":"已取消，未生成报销单"}`。重复确认返回 400 `E_NO_PENDING_DRAFT`。

### 2.6 其他

| 接口 | 说明 |
| --- | --- |
| `DELETE /api/sessions/{id}` | 删会话（连带消息，逻辑删除） |
| `GET /my/drafts` | 我的报销单列表页（HTML） |
| `GET /chat` | 聊天页（HTML） |
| `GET /healthz` | `{ok, llm:"online"|"offline", model, db}` |

## 3. 前端设计（单页，原生 JS，零框架）

```
┌──────────┬──────────────────────────────────────────────┐
│ 会话列表  │  消息流                                       │
│ +新建     │   ┌ 用户气泡 ────────────────┐                │
│          │   └──────────────────────────┘                │
│ 今天      │   ┌ 助手气泡 ─────────────────────────────┐    │
│ · 上海出差 │   │ ● 正在检索制度…（状态条）              │    │
│ · 发票问题 │   │ 上海属一线城市，普通员工住宿上限…       │    │
│          │   │ ▸ 调用了 search_policy（3 轮）         │    │
│          │   │ ┌ 引用来源（3）─ 折叠 ─────────────┐    │    │
│          │   │ │ [1] 2.2 住宿标准 · 500 元/晚      │    │    │
│          │   │ └──────────────────────────────────┘    │    │
│          │   └────────────────────────────────────────┘    │
│          │   ┌ 确认卡片 ──────────────────────────────┐    │
│          │   │ 差旅报销单草稿  合计 ¥480.00            │    │
│          │   │ 住宿费 480.00  2026-10-20  发票 87654321│    │
│          │   │ 审批：直属主管 → 财务审核 → 出纳付款     │    │
│          │   │ [确认建单]  [取消]                      │    │
│          │   └────────────────────────────────────────┘    │
│          │   [输入框……………………………] [发送]              │
└──────────┴──────────────────────────────────────────────┘
```

三个硬要求与实现方式：

| 要求 | 实现 |
| --- | --- |
| 打字机效果 | `createTypewriter(12ms/2字)`：收到的 token 进队列，定时器按 2 字/12ms 消费，队列空则停表。**不用 CSS 动画**，因为首字延迟必须反映真实首包时间 |
| "正在检索制度…" | `status` 事件驱动；收到第一个 `token` 时自动隐藏 |
| 引用来源（文件名+片段） | `citations` 事件渲染可折叠卡片，标题 `[n] heading`，正文截断 160 字，点击展开全文 |

### 3.1 SSE 解析为什么要手写

`EventSource` 有三个问题：只能用 GET（问题会进 URL 日志）、不能带自定义头、断线自动重连会导致重复提问。所以用 `fetch` + `ReadableStream`，手写按 `\n\n` 切帧、按 `data: ` 取载荷：

```js
// app/web/static/chat.js
const reader = res.body.getReader(); const dec = new TextDecoder();
let buf = "";
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  buf += dec.decode(value, { stream: true });
  let i;
  while ((i = buf.indexOf("\n\n")) >= 0) {
    const frame = buf.slice(0, i); buf = buf.slice(i + 2);
    for (const line of frame.split("\n"))
      if (line.startsWith("data: ")) handleEvent(JSON.parse(line.slice(6)), ctx);
  }
}
```

### 3.2 一个真实踩过的 bug

最初把 `handleEvent` 定义在 `try/finally` 块内部，结果流式循环里调用时 `ReferenceError`——闭包里能看到它，但后续帧的执行上下文取不到。重构为**模块级 `handleEvent(evt, ctx)`**，把所有可变状态收进 `ctx = { shell, typer, citationsBox, confirmShown }`，才稳定下来。

## 4. 会话与历史的处理

- **每请求带最近 6 轮历史**（`history_rounds=6`，即 12 条消息）：`build_llm_history()` 从 `messages` 表取倒序 12 条再翻转，保证代词指代（"那这张呢"）能接上。
- 历史里**只带 user/assistant 的正文**，不带工具调用中间态——否则上下文会被 `tool_result` 的 JSON 撑爆。
- 未登录访问 `/chat` 走 303 到 `/login?next=/chat`，`_safe_next()` 只允许站内相对路径，防开放重定向。
